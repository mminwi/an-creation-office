HOW TO USE THIS (every bot)
Follow the office-startup skill. This file is the office rule that skill carries out. Do not keep a second copy of the skill's steps here.

One shared library: AN-Creation/sops/library.txt in the project folder (Google Drive by default; the an-creation repository for GitHub offices), one copy and one version for every office. Each office reads its working copy (/workspace/offices/<your role>/sops/library.txt on Drive offices, the clone on GitHub offices). Read the one procedure you need from that file, then open https://ancreationoffice.com/version.txt?t=<today's date>. If the site does not open, carry on with the local library.txt.

The bot's copy is library.txt plus VERSION. https://ancreationoffice.com/sops-manifest.txt is the list the bundle is built from (Office version on the first line, then one path per line), including the resource library: resources.json, resources.txt, planning-resources.*, resource-crosscheck.*, sop-resource-map.txt, and every resources-*.html shelf. library.txt has the same version on its first line, then every one of those files in full, each after a line `=== FILE: <path> ===`. The file is about 2 MB. Read one section by its marker. The way to pull a section is in https://ancreationoffice.com/version-control.txt. The separate pages stay on the site for people.
A refresh is one download of https://ancreationoffice.com/library.txt, saved as AN-Creation/sops/library.txt, then VERSION. VERSION holds "Library version" and "SOP updates". SOP updates is auto, ask, or pinned. If the line is missing, it is ask. Keep the existing SOP updates line. Set Library version to this Office version.
- auto: when the site is newer, one bot downloads library.txt and continues. Every other bot pulls.
- ask: tell Mike what CHANGES says is new, and wait for a yes. Keep working from the local library.txt until then.
- pinned: ignore a newer site.
On Drive, the refresh is one upload over AN-Creation/sops/library.txt plus VERSION, read back. On GitHub it is one commit (never force-push main). office-save does either. From a creation-office checkout, python3 scripts/build-sop-library.py writes the manifest and library.txt. The files to save are library.txt and VERSION.

The only place a bot records a version it has seen is the "Office version seen" line in its office.txt. That line is this file's "Office version:" value, format YYMMDD.N, not a file revision. Project Manager Bot: AN-Creation/office.txt. Office Manager Bot: AN-Creation/Business/office.txt. Every other office: office.txt in that office's folder. Do not write version-seen.txt, and do not put that line in business.txt. If AN-Creation/Business/version-seen.txt still exists, copy its number into AN-Creation/Business/office.txt once when that line is empty, then delete version-seen.txt.

When the library you are using is newer than "Office version seen", re-read your office file from library.txt, tell the owner in one line what changed, and write the new Office version on that line.

If your profile version here is newer than your profile, set your own description from the short block in profile.txt and your title, with your profile tool (fallback: the owner pastes it). Read the profile back. Then run office-setup-check.

"What version are you on?": the Office version, the library version, and your profile version.
