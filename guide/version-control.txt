AN Creation backups and version control. Revision 3 — October 11, 2026. Human page: https://ancreationoffice.com/version-control.html
Replaces revision 2 (Git on the inventor's own computer). The office is cloud only now (D-098): Google Drive by default, GitHub for people comfortable with it.

WHY
AI is new, and it goofs up: a file gets overwritten, two versions get mixed, a chat gets cleared, a bot gets deleted. In practice, going back to an earlier version is close to a daily event. So the office never depends on one copy of anything, and never on the chat.

GOOGLE DRIVE (the default)
Nothing to install or set up. Three things keep the history:
- Never overwrite (D-029). Every update is a new dated file or folder: a new status, a new page, a new drawing, a new analyst run. The old one stays exactly as it was.
- Drive's own version history. Drive keeps earlier versions of each file. Google Docs and Sheets keep theirs for good; other files (text, CSV, images) keep about 30 days or 100 versions. The dated-file rule is what keeps the long history; Drive's versions are the safety net for a slip.
- The record. Every conversation and every analyst run is saved in Soren's files/record/ and sessions/, so what was said and decided is never only in a chat.
Say it to the inventor once, in a line: "Every change goes in a new dated file, so nothing gets lost, and Drive keeps earlier versions too."

GITHUB (if they're comfortable with it)
A private GitHub repository is a cloud folder with a full history of every change built in.
- The person creates the GitHub account themselves; account creation can't be automated. They connect GitHub in their AI app once.
- Create the repository as private (an-creation). Confirm it shows as private before the first save.
- Save a commit at the end of every conversation and every analyst run, with a short note: which invention, what changed, who (Soren or the analyst). Soren does it; the person doesn't have to.
- Plain words: repository = the project's online folder, commit = a saved checkpoint. Say the real word once, then use it (D-040).
- Big CAD and image files: keep them in a dated folder in Google Drive and link them, or use Git LFS (large file storage) if they know it.

IF SOMETHING GOES WRONG
- A file got overwritten, mixed up or deleted: look at the earlier dated files first, then Drive's version history (or the GitHub history), find the last good version, restore it as a new dated file, and say what was restored.
- A chat got cleared, or Soren was deleted and made again: nothing is lost. The new Soren looks for AN-Creation in My Drive first, reads office.txt, All inventions, PROJECT.txt, plan.md and the latest status, and carries on.
- They lost their phone: sign in to the same Google account (and AI app) on the new one. The files are in the cloud.

NEVER
- Never set the office up on a computer's own drive. It must work from the phone and be findable by a re-made Soren.
- Never put passwords, keys, an SSN, or bank or card numbers in any project file, note or commit message.
- A saved version is not an approval. History does not replace the revision and change records (sop-change-control.txt) or the record of what was sent to whom.
