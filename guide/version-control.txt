AN Creation backups and version control. Revision 2 — October 8, 2026. Human page: https://ancreationoffice.com/version-control.html
Replaces revision 1 (the three-vault layout and the old assistant names).

WHY
AI is new, and it goofs up: a file gets overwritten, two versions get mixed, a chat gets cleared, a computer dies. Without Git there is a very good chance that something gets mixed up and a revision is lost. In practice, going back into the Git history to recover something is close to a daily event. So we very, very highly recommend Git. Dated folders (D-029) already keep every page and analyst run; Git keeps a saved history of everything else, and a second copy protects against losing the computer.

THE DEFAULT: GIT ON THEIR OWN COMPUTER (recommend it strongly at setup)
Git keeps a saved history of the project folder on the person's own computer. No account, no internet, free.
- Help them install Git from the official site: https://git-scm.com/downloads/ . If you can't run the installer yourself, say exactly what to click.
- Make the AN-Creation folder one vault (repository). One vault for all their inventions is simplest; each invention is a folder inside it.
- Before the first checkpoint, add a .gitignore that leaves out passwords, keys, .env files and temporary files. Never commit an SSN, bank or card number, or password.
- Save a checkpoint (commit) after every conversation and every analyst run, with a short note: which invention, what changed, who (Soren or the analyst). Soren runs it; the person doesn't have to.
- Before restoring or redoing anything that looks wrong, check the history first: what changed, when, and the last good version.
- Plain words: vault = repository, checkpoint = commit, send to the online copy = push. Say the real word once, then use it (D-040).
If they decline, record it as a decision, say once what it risks, and offer again later.

THE OFFSITE COPY: GITHUB IF THEY WANT IT (offer, don't push)
Local Git protects versions, not the disk. If the computer is lost, so is the history. Offer a second copy:
- GitHub, a private repository: an online copy only they (and people they invite) can see. Check current plans and limits when setting up.
- The person creates the GitHub account themselves; account creation can't be automated. Prefer a browser sign-in (GitHub CLI: https://cli.github.com/manual/gh_auth_login ) over keys.
- Create the repository as private. Confirm it shows as private before the first push.
- After that, push after each checkpoint, or at the end of each day, as they choose. Don't ask permission again for every routine push.
- Big CAD and image files: use Git LFS (large file storage) on GitHub, or keep the largest files out of Git and back them up separately.
Other ways to keep a second copy are fine: an external drive, a synced cloud folder. Any copy that isn't on the same disk counts.

IF SOMETHING GOES WRONG
- A file got overwritten, mixed up or deleted: find the last good checkpoint, restore it, and say what was restored.
- A chat got cleared: nothing is lost; the project is in the files. Start from PROJECT.txt, plan.md and the latest status.
- The computer is gone: clone the GitHub copy (or restore the drive copy) onto the new computer, and check the latest checkpoint is there.
Once, after setup, test it: restore one file from a checkpoint, and if there is an online copy, clone it into a scratch folder and look.

LIMITS
A checkpoint is not an approval. Git history does not replace the revision and change records (sop-change-control.txt) or the record of what was sent to whom. Never put passwords or tokens in PROJECT.txt, notes or checkpoint messages.
