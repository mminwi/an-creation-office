AN Creation backups and version control. Revision 6 — October 14, 2026. Human page: https://ancreationoffice.com/version-control.html
Replaces revision 3 (Google Drive default). The office lives in a private GitHub repository (D-100).

WHY
AI is new, and it goofs up: a file gets overwritten, two versions get mixed, a chat gets cleared, a bot gets deleted. In practice, going back to an earlier version is close to a daily event. So the office never depends on one copy of anything, and never on the chat.

HOW IT'S KEPT
- GitHub keeps every committed version. The project is a private repository (an-creation). Each office has its own clone and follows the office-save skill: one commit per turn.
- The shared procedure library is AN-Creation/sops/library.txt in that repository (mminwi/an-creation), plus AN-Creation/sops/VERSION. One version for every office. library.txt is about 2 MB. Its first line is the Office version. Each file follows on its own, in full, after a marker line `=== FILE: <path> ===`. That includes the resource library (resources.json, resources.txt, planning-resources.*, resource-crosscheck.*, sop-resource-map.txt, and every resources-*.html shelf). Read one section by its marker. To pull standing.txt: awk '$0=="=== FILE: standing.txt ==="{p=1;next} /^=== FILE: /{p=0} p' AN-Creation/sops/library.txt. Use the path you need in place of standing.txt. office-startup reads the library this way. A refresh is one download of https://ancreationoffice.com/library.txt and one commit, with VERSION rewritten beside it. The separate pages stay on the site for people. The rule is https://ancreationoffice.com/version.txt
- Two kinds of files (D-029). Working files stay current by design and are updated in place: office.txt, business.txt, plan.md, actions.csv, team.csv, the hand-off inboxes, Status and Plan (earlier Status and Plan copies also go to History/). GitHub's history keeps every earlier version of them. Records and outputs are never edited once saved: documents, drawings, pages, analyst runs, record/ entries, released revisions. A change to one is a new dated file or a new revision, and the old one stays exactly as it was.
- The record. Every conversation and every analyst run is saved in record/ and sessions/, so what was said and decided is not only in a chat. Anything not yet saved is only in the chat.
Plain words: repository = the project's online folder, commit = a saved checkpoint. Say the real word once, then use it (D-040). Say it to the owner once, in a line: "Your work is saved to GitHub as we go, and GitHub keeps every earlier version."

SAVING (every office and b-analyst)
Follow the office-save skill. This is the office rule it carries out.
- Your own clone: /workspace/offices/<your role>/an-creation. Never a shared clone, and never /workspace/repo.
- The GitHub connector is read-only. Looking can use it. Saving cannot.
- One commit per turn, not one commit per answer. The note says which job, what changed, and the role.
- pull --rebase before the commit. If the push is rejected, pull --rebase and push again.
- After the push, read the file back with gh and confirm it matches. Unpushed work is not saved. A push you did not read back is not confirmed.
- Quiet when it works. A failed save is one plain line to the owner. Never call it saved when the read-back failed.
- Never force-push main. This free private repository cannot turn on branch protection (that needs GitHub Pro), so you keep the rule.
- A work branch is named by role, for example b-project-manager/<topic>, and deleted after it merges. Do not open a claude/* or cursor/* branch.
- End of a conversation: one "Last saved" line in your office.txt (time, commit, what). office-save confirms it.
- Files over about 50 MB stay out of the repository. Record where the original lives.
Refreshing the library downloads https://ancreationoffice.com/library.txt once, writes it to AN-Creation/sops/library.txt, and rewrites VERSION (Library version and SOP updates). That is one commit for that library version. office-startup decides whether to refresh. office-save makes the commit. Read a section with the awk line above. The file is about 2 MB, so read one section.
Setup: https://ancreationoffice.com/github-setup.txt

IF SOMETHING GOES WRONG
- A file got overwritten, mixed up or deleted: look at the earlier dated files first, then the file's history on GitHub, find the last good version, restore it as a new commit, and say what was restored.
- A chat got cleared, or a bot was deleted and made again: everything that was saved is still there. The new bot looks for the an-creation repository first, reads office.txt (its "Last saved" line), All inventions, PROJECT.txt, plan.md and the latest status, and carries on from the last saved checkpoint. Anything said after the last save was only in the old chat: ask the owner about it.
- They lost their phone: sign in to GitHub and their AI app on the new one. The project is in the cloud.

NEVER
- The record is the private GitHub repository. Each office's working copy is its own clone, /workspace/offices/<role>/an-creation, on the shared computer. Never /workspace/repo, and never a clone shared with another office.
- Never make the repository public.
- Never put passwords, keys, an SSN, or bank or card numbers in any project file, issue or commit message.
- A saved version is not an approval. History does not replace the revision and change records (sop-change-control.txt) or the record of what was sent to whom.
- Big CAD, video and image files (over about 50 MB): keep them out of the repository and record where they are (SAVING 7).
