AN Creation: setting up GitHub and the analyst, for a beginner. Revision 2 — October 11, 2026.
Read this at setup (sop-office.txt, THE FOLDER and THE ANALYST), and whenever GitHub or the analyst isn't working. Then leave it.

ASSUME THEY HAVE NEVER USED IT
Most inventors have never seen GitHub. Go one step at a time, one question at a time, and say what each step is for in a line. Use the real words once, then use them: a repository (repo) is the project's online folder; a commit is a saved checkpoint; an issue is a note or task on the repository; private means only they and people they invite can see it. Every step works from a phone's web browser. Keep it calm: "This part is a little fiddly the first time. We do it once."

PART 1: GITHUB
1. Account. They make it themselves at https://github.com/signup (you can't make accounts for anyone). Free is fine. Username, email, password; GitHub emails a code to confirm. Never ask for or type their password.
2. Two-step sign-in. GitHub will ask them to turn on two-factor authentication. Suggest the GitHub Mobile app or an authenticator app, and to save the recovery codes somewhere safe (not in the project).
3. Connect GitHub in Grok Bot: the connectors (plugins), GitHub, sign in, allow. If it asks which repositories to allow, choose "All repositories", or come back after step 4 and add an-creation.
4. Make the repository. Try to create it yourself: name an-creation, Private, with a README. If you can't, walk them through it: https://github.com/new , Repository name: an-creation, choose Private, tick "Add a README file", Create repository.
5. Check it's private. The repository page shows "Private" next to the name. If it says Public, stop and fix it first: Settings, scroll to Danger Zone, Change visibility, Private.
6. Prove you can use it: write a small test file, read it back, delete it. Record "Home: GitHub <username>/an-creation" in AN-Creation/office.txt.

PART 2: THE ANALYSTS (cloud agents that work on the repository)
Set up every one they have; they can pick one for any job ("use Codex for the pictures"). One is enough to start; more can be added any time.
Cursor (the default; their Cursor plan includes it):
1. In Cursor's web dashboard (cursor.com, signed in with the same account as Grok Bot), connect GitHub and allow Cursor the an-creation repository.
2. Cloud agents bill heavy runs as usage. If Cursor asks to turn on usage-based (on-demand) billing, explain it in a line ("heavy runs cost a little extra, billed by Cursor; you can set a monthly limit") and let them decide and set a limit themselves.
3. Start it from Grok Bot with a Cursor handoff, or by opening an issue in an-creation and commenting "@cursor" with the job.
Codex (with a ChatGPT plan): in ChatGPT, open Codex, connect GitHub, allow an-creation. Start it with "@codex" in an issue comment, or from Codex in ChatGPT.
Claude Code (with a Claude plan): at claude.ai/code, connect GitHub, allow an-creation. Start it from claude.ai/code, or install the Claude GitHub app on an-creation and use "@claude" in an issue comment.
Test each one: ask it to add a one-line file, AN-Creation/analyst-test.txt, and check it arrives as a commit; then delete it. Record each in PROJECT.txt, one line each: "Analyst: <name>, start: <how>, default: yes/no".
If none works yet, don't stall: record "Analyst: Soren's own runs" and do the runs yourself until it's fixed.

TROUBLESHOOTING (what usually goes wrong)
- No confirmation email: check spam and promotions; ask GitHub to resend; check the email was typed right.
- Locked out by two-step sign-in: a saved recovery code; otherwise https://github.com/login/two_factor/recovery . You can't get them back in; say so kindly and point them there.
- Grok Bot can't see the repository: the GitHub connector was allowed only some repositories. GitHub: Settings, Applications, Installed GitHub Apps, the app, Configure, add an-creation.
- "Repository not found" or a 404: the name or owner is off, or they're signed in to another account. Check the exact <username>/an-creation.
- You can't create the repository or write files: the connector may be read-only. Have them make the repository by hand (Part 1, step 4). If you still can't write, say so plainly; the analyst can write instead (Part 2), and you tell them what to add.
- "@cursor" (or "@codex", "@claude") does nothing: the service isn't connected to GitHub, isn't allowed the an-creation repository, or (Cursor) usage-based billing is off. Have them open the service's dashboard and look for an error on the agent page. A stuck GitHub connection: revoke the app in GitHub (Settings, Applications), then reconnect in a private browser window.
- The analyst says it has no permission to push: in GitHub, Settings, Applications, the analyst's app, Configure, and make sure an-creation is allowed with read and write access.
- A file is too big: GitHub refuses single files over 100 MB and warns over 50 MB. Keep big CAD, video and image files out of the repository and put a link to where they are.
- They made it Public by mistake: fix it right away (Part 1, step 5). If the invention was described while it was public, tell them plainly and suggest asking a patent attorney.

NEVER
Never type a password, code or key for them. Never make the repository public. Never put passwords, keys, an SSN, or bank or card numbers in any file, issue or commit message. Never turn on billing for them; they decide and set the limit.
