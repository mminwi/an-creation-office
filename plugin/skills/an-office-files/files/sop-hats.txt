Where it disagrees with https://ancreationoffice.com/analyst.txt, https://ancreationoffice.com/sop-focus.txt or https://ancreationoffice.com/sop-stages.txt, those win.

Read this to create a Grok Build session, or to split one that is overloaded. Which subject deserves a new session is in https://ancreationoffice.com/sop-routes.txt. After the session exists and you are only working it, leave this file.

Older notes called this session a hat. The word now is session. A role is the one-word job b-project-manager is doing. The session is the Grok Build instance that keeps that subject.

A session keeps a related series of documents, because each sheet mostly comes from the sheet before it. About twenty to thirty items that trade off against each other belong in one session. One item per session is too small. Those items never see each other’s tradeoffs.

Give the session a new id and write it in plan.md before the first real task. A second filing, a second deal, or a second area is a second row. b-project-manager calls all of them. The role on the row says which job it is doing.

Role. One word: project, design, legal, engineering, prototype, manufacturing, funding, or marketing.
Subject. The thing, such as Enclosure chain, or SBIR for the battery test.
Tracks. The series, such as desires through the test plan for the enclosure, or this one grant.
Session id. The UUID you pass to grok --session-id when you create it.
Call it when. The words that should resume this id.
Status. Open while the work is live. Closed when the inventor shuts that branch. A closed row keeps its session id and is not resumed.

Start it in the project folder:

grok --session-id <uuid>

Tell it the project path, the role, the series it owns, the sheets it may edit, and the short standing rules for that series. Resume it later with:

grok --resume <uuid>

Do not use a plain resume when more than one session uses the folder. That opens whichever session ran last.

b-project-manager calls the session. The inventor does not. A call is an inventor update that touches that series, a neighboring session moving a shared edge, or a review before the sheets are treated as current. The session re-reads its sheets, updates the few items in front of it, and reports: which item changed, what is written, what is unknown, and which other items were affected. b-project-manager writes what belongs in plan.md. b-project-manager tells the inventor when a person has to choose.

Working files stay in the subject folders. The session transcript stays in the Grok home. The session id in plan.md is how you get back.

Split a session when its items rarely change one another, or when a new set of requirements does not fit the series. Electrical and battery items can be one engineering session. Structure, fits, and seals can be another. Two areas that only meet at an edge stay apart. The meeting is handled by the integrator in https://ancreationoffice.com/sop-quality.txt when the series is the quality chain.

If clamping and holding share the same parts and every change to one rewrites the other, they are one session. If they meet at a mount and a load, they are two sessions.

A cross-area choice gets one short interface note both sessions can read: the item ids, the conflict, and the decision. Neither session absorbs the other session’s sheets.

For customer desires, the specification, failure modes, the control plan, and the test plan, leave this file and follow https://ancreationoffice.com/sop-quality.txt
For one job that should end, follow https://ancreationoffice.com/sop-interns.txt
If b-project-manager itself is missing, follow https://ancreationoffice.com/sop-office.txt

Done when plan.md has the row, the session has done one real pass, and b-project-manager has the report. The setup text does not stay in the session’s context. The session keeps the short standing rules for its own series.
